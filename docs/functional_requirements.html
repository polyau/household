Функциональные требования

В данном разделе описываются функциональные требования к MVP и критерии их приёмки.

FR-01 — Вход в приложение

РазделОписание
IDFR-01
НазваниеВход в приложение
АкторыПользователь
Предусловия• Приложение установлено
• У пользователя есть интернет-соединение
Постусловия (Успех)• Пользователь авторизован
• Открыто главное меню со списком пространств и возможностью создать/войти в пространство
Постусловия (Неудача)• Пользователь не авторизован
• Отображено сообщение об ошибке
Основной поток1. Пользователь открывает приложение.
2. Пользователь выбирает "Вход".
3. Пользователь вводит логин и пароль.
4. Пользователь нажимает "Войти".
5. Система проверяет учётные данные.
6. Система выполняет авторизацию и открывает главный экран.
Альтернативный поток 1Регистрация
Точка входа: шаг 2

2.1 Пользователь выбирает "Регистрация".
2.2 Пользователь вводит регистрационные данные.
2.3 Система создаёт учётную запись.
2.4 Система выполняет авторизацию и открывает главный экран.
Альтернативный поток 2Восстановление доступа
Точка входа: шаг 3

3.1 Пользователь выбирает "Не помню пароль".
3.2 Система предлагает сценарий восстановления доступа.
Исключительный поток 1 (ошибки)Неверные учётные данные
Точка входа: шаг 5

5.1 Система отклоняет вход.
5.2 Система отображает сообщение "Неверный логин или пароль".
Исключительный поток 2Блокировка после неудачных попыток
Точка входа: шаг 5

5.1 После 5 неудачных попыток система блокирует возможность входа в данную учётную запись на 15 минут.
5.2 Система отображает сообщение о блокировке и времени ожидания.
Бизнес-правилаBR-01: Без авторизации пользователь не может создавать пространства и работать с ними.

РазделОписание
IDFR-02
НазваниеСоздание пространства
АкторыПользователь
ПредусловияПользователь авторизован
Постусловия (Успех)• Пространство создано
• Пользователь назначен администратором пространства
• Сгенерирован код приглашения
Постусловия (Неудача)• Пространство не создано
• Отображено сообщение об ошибке
Основной поток1. Пользователь открывает приложение.
2. Пользователь нажимает "Добавить пространство".
3. Пользователь выбирает "Создать пространство".
4. Пользователь вводит название пространства.
5. Пользователь нажимает "Создать".
6. Система проверяет, что название пространства заполнено.
7. Система создаёт пространство.
8. Система назначает пользователя администратором пространства.
9. Система генерирует код приглашения.
10. Система открывает экран созданного пространства.
Альтернативный поток 1Отмена
Точка входа: шаг 4

4.1 Пользователь нажимает "Отмена".
4.2 Система возвращает пользователя на список пространств без изменений.
Исключительный поток 1 (ошибки)Отсутствует название
Точка входа: шаг 6

6.1 Система не создаёт пространство.
6.2 Система отображает сообщение о необходимости указать название.
Бизнес-правилаBR-02: Создатель пространства получает роль "администратор".

FR-03 — Приглашение участника

РазделОписание
IDFR-03
НазваниеПриглашение участника
АкторыАдминистратор пространства
Предусловия• Пользователь авторизован
• Пользователь является администратором выбранного пространства
Постусловия (Успех)Код приглашения отображён и доступен для передачи приглашённому пользователю
Постусловия (Неудача)• Код приглашения не отображён/не обновлён
• Отображено сообщение об ошибке
Основной поток1. Администратор выбирает пространство.
2. Администратор открывает настройки пространства.
3. Администратор выбирает "Пригласить участника".
4. Система отображает код приглашения.
5. Администратор передаёт код приглашаемому пользователю.
Альтернативный поток 1Сгенерировать новый код
Точка входа: шаг 4

4.1 Администратор нажимает "Сгенерировать новый код".
4.2 Система блокирует предыдущий код приглашения (недействителен).
4.3 Система генерирует новый код приглашения.
4.4 Система отображает новый код.
Исключительный поток 1 (ошибки)Нет прав
Точка входа: шаг 3

3.1 Система не предоставляет доступ к функции приглашения.
3.2 Система отображает сообщение об отсутствии прав.
Бизнес-правилаBR-03: Управление кодом приглашения доступно только администратору пространства.
BR-04: При генерации нового кода предыдущий код считается недействительным.

Постусловия (Успех)• Пользователь добавлен в пространство с ролью "участник"

Постусловия (Неудача)• Пользователь не добавлен в пространство

5. Пользователь нажимает "Присоединиться".
6. Система проверяет код приглашения.
7. Система добавляет пользователя в пространство с ролью "участник".

Точка входа: шаг 6

6.2 Система отображает сообщение "Неверный код приглашения".
Бизнес-правилаBR-05: По коду пользователь может присоединиться только к существующему пространству.

FR-05 — Создание задачи по дому

РазделОписание
IDFR-05
НазваниеСоздание задачи по дому
Акторы• Участник пространства
• Сервис push-уведомлений
Предусловия• Пользователь авторизован
• Пользователь является участником пространства
Постусловия (Успех)• Задача создана и отображается в списке задач пространства
• Если выбрано "Добавить в календарь" - задача отображается в календаре пространства
• Если назначен исполнитель/указан дедлайн - отправлено push-уведомление
Постусловия (Неудача)• Задача не создана
• Отображено сообщение об ошибке
Основной поток1. Пользователь открывает в пространстве раздел "Задачи".
2. Пользователь нажимает "Создать задачу".
3. Пользователь вводит название задачи.
4. Пользователь выбирает исполнителя из участников пространства.
5. Пользователь при необходимости задаёт дедлайн, повторяемость, добавление задачи в календарь.
6. Система проверяет, что дедлайн, если он указан, не в прошлом.
7. Пользователь нажимает "Сохранить".
8. Система проверяет, что название задачи задано
9. Система создаёт задачу со статусом "активна".
10. Система добавляет задачу в календарь пространства (если включена опция).
11. Система отправляет push-уведомление исполнителю о назначении/дедлайне.
Альтернативный поток 1Без назначения исполнителя
Точка входа: шаг 4

4.1 Пользователь не выбирает исполнителя.
4.2 Система считает задачу назначенной на всех участников пространства.
Исключительный поток 1Дедлайн в прошлом
Точка входа: шаг 6

6.1 Система обнаружила, что дедлайн в прошлом времени.
6.2 Система помечает поле ввода дедлайна красным цветом с подписью под полем "Дедлайн не может быть в прошлом".
Исключительный поток 2Отсутствует название
Точка входа: шаг 8

8.1 Пользователь не задал название задачи.
8.2 Система отображает сообщение об ошибке и просит задать название задачи.
Бизнес-правилаBR-06: Название задачи обязательно.
BR-07: Исполнителем может быть только участник данного пространства.
BR-08: Дедлайн не может быть в прошлом.

FR-06 — Отметка выполнения задачи

РазделОписание
IDFR-06
НазваниеОтметка выполнения задачи
АкторыУчастник пространства
Предусловия• Пользователь авторизован
• Пользователь является участником пространства
• В пространстве есть активная задача
Постусловия (Успех)• Задача переведена в статус "выполнено"
• Если задача повторяющаяся - создано следующее повторение согласно настройкам
Постусловия (Неудача)• Статус задачи не изменён
• Отображено сообщение об ошибке
Основной поток1. Пользователь открывает раздел пространства со списком задач.
2. Пользователь выбирает задачу.
3. Пользователь нажимает "Отметить выполненной".
4. Система меняет статус задачи на "выполнено".
5. Если у задачи задана повторяемость - система создаёт следующую задачу по расписанию.
Альтернативный поток 1Снять отметку выполнения
Точка входа: шаг 4

4.1 Пользователь снимает отметку "выполнено".
4.2 Система возвращает задачу в активный статус.
Исключительный поток 1 (ошибки)Недостаточно прав на изменение задачи
Точка входа: шаг 4

4.1 Система не изменяет статус задачи.
4.2 Система отображает сообщение об отсутствии прав.
Бизнес-правилаBR-09: Если задаче назначен исполнитель - изменять статус может исполнитель и администратор пространства; если исполнитель не назначен - любой участник пространства.
BR-10: Повторяемость применяется только к задачам с включённой повторяемостью.

FR-08 — Создание события в календаре пространства

РазделОписание
IDFR-08
НазваниеСоздание события в календаре пространства
Акторы• Участник пространства
• Сервис push-уведомлений

• Пользователь является участником выбранного пространства

Точка входа: шаг 8

Критерии приёмки​

Критерии приемки к FR-01: Вход в приложение

Основной сценарий:

  • При вводе корректных учётных данных пользователь успешно авторизуется
  • После входа открывается главный экран со списком пространств и возможностью создать/войти в пространство

Альтернативный сценарий:

  • При выборе "Регистрация" пользователь может создать учётную запись и после успешной регистрации попадает на главный экран
  • При выборе "Не помню пароль" система запускает сценарий восстановления доступа (отображает соответствующий экран/инструкции)

Валидация формата:

  • Пустые поля логина/пароля не принимаются, отображается сообщение об ошибке

Проверка условий:

  • При неверных учётных данных отображается сообщение "Неверный логин или пароль"
  • После 5 неудачных попыток входа вход в данную учётную запись блокируется блокируется на 15 минут и отображается сообщение о блокировке

Сохранение данных:

  • При успешном входе создаётся/обновляется пользовательская сессия
  • При ошибке входа пользователь не авторизуется и сессия не создаётся

Критерии приемки к FR-02: Создание пространства

Основной сценарий:

  • Пространство создаётся, если название указано
  • Создатель пространства получает роль "администратор"
  • Сгенерирован код приглашения
  • Созданное пространство отображается в списке пространств пользователя и открывается после создания

Валидация формата:

  • Если название не указано, система отображает сообщение об ошибке

Сохранение данных:

  • При успехе сохраняются данные пространства и роль создателя "администратор"
  • При ошибке пространство не создаётся

Критерии приемки к FR-03: Получение кода приглашения

Основной сценарий:

  • Администратор может открыть экран приглашения и увидеть код приглашения
  • Администратор может передать код приглашённому пользователю

Проверка условий:

  • Пользователь без роли администратора не имеет доступа к получению/управлению кодом приглашения
  • После генерации нового кода отображается новый код (отличается от предыдущего)

Сохранение данных:

  • При генерации нового кода новый код сохраняется для пространства

Критерии приемки к FR-04: Присоединение к пространству по коду

Основной сценарий:

  • При вводе корректного кода пользователь добавляется в пространство как "участник"
  • Пространство появляется в списке пространств пользователя
  • Пространство открывается после успешного присоединения

Проверка условий:

  • При недействительном коде отображается сообщение "Неверный код приглашения"
  • Если пользователь уже состоит в пространстве - система сообщает об этом и открывает пространство

Сохранение данных:

  • При успехе сохраняется связь "пользователь-пространство" и роль "участник"
  • При ошибке присоединения пользователь не добавляется в пространство

FR-03 + FR-04:

  • При генерации нового кода предыдущий код становится недействительным (попытка присоединиться по старому коду приводит к ошибке "Неверный код приглашения")

Критерии приемки к FR-05: Создание задачи по дому

Основной сценарий:

  • Задача создаётся и отображается в списке задач пространства
  • При выборе исполнителя задача создаётся с назначенным исполнителем
  • При включении опции "Добавить задачу в календарь" задача отображается в календаре пространства
  • При назначении исполнителя отправляется push-уведомление о назначении
  • При наличии дедлайна отправляется push-уведомление о дедлайне

Проверка условий:

  • Если исполнитель не выбран, задача создаётся без исполнителя, push о назначении не отправляется
  • Если дедлайн не задан, задача создаётся, push о дедлайне не отправляется

Валидация формата:

  • Пустое название задачи отклоняется с сообщением об ошибке
  • Дедлайн в прошлом отклоняется с сообщением об ошибке

Бизнес-правила:

  • Исполнителем может быть только участник данного пространства

Сохранение данных:

  • При успехе сохраняются данные задачи: название (обязательно), исполнитель/дедлайн/повторяемость/привязка к календарю - если указаны
  • При ошибке задача не создаётся

Критерии приемки к FR-06: Отметка выполнения задачи

Основной сценарий:

  • Статус задачи меняется на "выполнено"
  • Если задача повторяющаяся - создаётся следующее повторение по расписанию

Бизнес-правила:

  • Если назначен исполнитель - статус может изменить исполнитель и администратор пространства
  • Если исполнитель не назначен - статус может изменить любой участник пространства

Сохранение данных:

  • При успехе сохраняется новый статус задачи и время выполнения

Критерии приемки к FR-07: Ведение списка покупок

Основной сценарий:

  • Позиция покупки добавляется в общий список и видна всем участникам пространства
  • Позицию можно отметить как "куплено"
  • Позицию можно отредактировать
  • Позицию можно удалить

Валидация формата:

  • Пустое название позиции отклоняется с сообщением об ошибке

Сохранение данных:

  • При успехе изменения списка сохраняются (добавление/редактирование/удаление/статус "куплено")
  • При ошибке изменения не сохраняются

Критерии приемки к FR-08: Создание события календаря пространства

Основной сценарий:

  • Событие создаётся и отображается в календаре пространства

Проверка условий:

  • Если выбраны участники - push о создании события отправляется выбранным участникам
  • Если участники не выбраны - push о создании события отправляется всем участникам
  • Если заданы сроки напоминаний - система отправляет push-напоминания в заданное время
  • Если сроки напоминаний не заданы - push-напоминания не отправляются

Валидация формата:

  • Пустое название события отклоняется с сообщением об ошибке

Сохранение данных:

  • При успехе сохраняются данные события (название, дата/время, участники/без)
  • При ошибке событие не создаётся
