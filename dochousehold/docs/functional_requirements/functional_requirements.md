В данном разделе описываются функциональные требования к MVP и критерии их приёмки.

**FR-01 — Вход в приложение**

|Раздел|Описание|
|-|-|
|**ID**|FR-01|
|**Название**|Вход в приложение|
|**Акторы**|Пользователь|
|**Предусловия**|• Приложение установлено<br />• У пользователя есть интернет-соединение|
|**Постусловия (Успех)**|• Пользователь авторизован<br />• Открыто главное меню со списком пространств и возможностью создать/войти в пространство|
|**Постусловия (Неудача)**|• Пользователь не авторизован<br />• Отображено сообщение об ошибке|
|**Основной поток**|1. Пользователь открывает приложение.<br />2. Пользователь выбирает "Вход".<br />3. Пользователь вводит логин и пароль.<br />4. Пользователь нажимает "Войти".<br />5. Система проверяет учётные данные.<br />6. Система выполняет авторизацию и открывает главный экран.|
|**Альтернативный поток 1**|**Регистрация**<br />Точка входа: шаг 2<br /> <br /> 2.1 Пользователь выбирает "Регистрация".<br /> 2.2 Пользователь вводит регистрационные данные.<br />2.3 Система создаёт учётную запись.<br />2.4 Система выполняет авторизацию и открывает главный экран.|
|**Альтернативный поток 2**|**Восстановление доступа**<br />Точка входа: шаг 3<br /> <br />3.1 Пользователь выбирает "Не помню пароль".<br />3.2 Система предлагает сценарий восстановления доступа.|
|**Исключительный поток 1 (ошибки)**|**Неверные учётные данные**<br />Точка входа: шаг 5<br /> <br />5.1 Система отклоняет вход.<br />5.2 Система отображает сообщение "Неверный логин или пароль".|
|**Исключительный поток 2**|**Блокировка после неудачных попыток**<br />Точка входа: шаг 5<br /> <br />5.1 После 5 неудачных попыток система блокирует возможность входа в данную учётную запись на 15 минут.<br />5.2 Система отображает сообщение о блокировке и времени ожидания.|
|**Бизнес-правила**|BR-01: Без авторизации пользователь не может создавать пространства и работать с ними.|

Пользователь вводит название пространства.<br />5. Пользователь нажимает "Создать".<br />6. Система проверяет, что название пространства заполнено.<br />7. Система создаёт пространство.<br />8. Система назначает пользователя администратором пространства.<br />9. Система генерирует код приглашения.<br />10. Система открывает экран созданного пространства.|

|**Исключительный поток 1 (ошибки)**|**Отсутствует название**<br />Точка входа: шаг 6<br /> <br />6.1 Система не создаёт пространство.<br />6.2 Система отображает сообщение о необходимости указать название.|
|**Бизнес-правила**|BR-02: Создатель пространства получает роль "администратор".|

**FR-03 — Приглашение участника**

|Раздел|Описание|
|-|-|
|**ID**|FR-03|
|**Название**|Приглашение участника|
|**Акторы**|Администратор пространства|
|**Предусловия**|• Пользователь авторизован<br />• Пользователь является администратором выбранного пространства|
|**Постусловия (Успех)**|Код приглашения отображён и доступен для передачи приглашённому пользователю|
|**Постусловия (Неудача)**|• Код приглашения не отображён/не обновлён<br />• Отображено сообщение об ошибке|
|**Основной поток**|1. Администратор выбирает пространство.<br />2. Администратор открывает настройки пространства.<br />3. Администратор выбирает "Пригласить участника".<br />4. Система отображает код приглашения.<br />5. Администратор передаёт код приглашаемому пользователю.|
|**Альтернативный поток 1**|**Сгенерировать новый код**<br />Точка входа: шаг 4<br /> <br />4.1 Администратор нажимает "Сгенерировать новый код".<br />4.2 Система блокирует предыдущий код приглашения (недействителен).<br />4.3 Система генерирует новый код приглашения.<br />4.4 Система отображает новый код.|
|**Исключительный поток 1 (ошибки)**|**Нет прав**<br />Точка входа: шаг 3<br /> <br />3.1 Система не предоставляет доступ к функции приглашения.<br />3.2 Система отображает сообщение об отсутствии прав.|
|**Бизнес-правила**|BR-03: Управление кодом приглашения доступно только администратору пространства.<br />BR-04: При генерации нового кода предыдущий код считается недействительным.|

**FR-04 — Присоединение к пространству** 

|Раздел|Описание|
|-|-|
|**ID**|FR-04|
|**Название**|Присоединение к пространству|
|**Акторы**|Пользователь|
|**Предусловия**|• Пользователь авторизован<br />• У пользователя есть код приглашения|
|**Постусловия (Успех)**|• Пользователь добавлен в пространство с ролью "участник"<br />• Пространство отображается в списке пространств пользователя|
|**Постусловия (Неудача)**|• Пользователь не добавлен в пространство<br />• Отображено сообщение об ошибке|
|**Основной поток**|1. Пользователь открывает список пространств.<br />2. Пользователь нажимает "Добавить пространство".<br />3. Пользователь нажимает "Добавить по коду".<br />4. Пользователь вводит код приглашения.<br />5. Пользователь нажимает "Присоединиться".<br />6. Система проверяет код приглашения.<br />7. Система добавляет пользователя в пространство с ролью "участник".<br />8. Система открывает экран пространства.|
|**Альтернативный поток 1**|**Пользователь уже состоит в пространстве**<br />Точка входа: шаг 7<br /> <br />7.1 Система сообщает, что пользователь уже является участником.<br />7.2 Система открывает пространство.|
|**Исключительный поток 1**|**Неверный код**<br />Точка входа: шаг 6<br /> <br />6.1 Система отклоняет присоединение.<br />6.2 Система отображает сообщение "Неверный код приглашения".|
|**Бизнес-правила**|BR-05: По коду пользователь может присоединиться только к существующему пространству.|

**FR-05 — Создание задачи по дому**

|Раздел|Описание|
|-|-|
|**ID**|FR-05|
|**Название**|Создание задачи по дому|
|**Акторы**|• Участник пространства<br />• Сервис push-уведомлений|
|**Предусловия**|• Пользователь авторизован<br />• Пользователь является участником пространства|
|**Постусловия (Успех)**|• Задача создана и отображается в списке задач пространства<br />• Если выбрано "Добавить в календарь" - задача отображается в календаре пространства<br />• Если назначен исполнитель/указан дедлайн - отправлено push-уведомление|
|**Постусловия (Неудача)**|• Задача не создана<br />• Отображено сообщение об ошибке|
|**Основной поток**|1. Пользователь открывает в пространстве раздел "Задачи".<br />2. Пользователь нажимает "Создать задачу".<br />3. Пользователь вводит название задачи.<br />4. Пользователь выбирает исполнителя из участников пространства.<br />5. Пользователь при необходимости задаёт дедлайн, повторяемость, добавление задачи в календарь.<br />6. Система проверяет, что дедлайн, если он указан, не в прошлом.<br />7. Пользователь нажимает "Сохранить".<br />8. Система проверяет, что название задачи задано<br />9. Система создаёт задачу со статусом "активна".<br />10. Система добавляет задачу в календарь пространства (если включена опция).<br />11. Система отправляет push-уведомление исполнителю о назначении/дедлайне.|
|**Альтернативный поток 1**|**Без назначения исполнителя** <br />Точка входа: шаг 4<br /> <br/>4.1 Пользователь не выбирает исполнителя.<br />4.2 Система считает задачу назначенной на всех участников пространства.|
|**Исключительный поток 1**|**Дедлайн в прошлом** <br />Точка входа: шаг 6<br /> <br />6.1 Система обнаружила, что дедлайн в прошлом времени.<br />6.2 Система помечает поле ввода дедлайна красным цветом с подписью под полем "Дедлайн не может быть в прошлом".|
|**Исключительный поток 2**|**Отсутствует название** <br />Точка входа: шаг 8<br /> <br />8.1 Пользователь не задал название задачи.<br />8.2 Система отображает сообщение об ошибке и просит задать название задачи.|
|**Бизнес-правила**|BR-06: Название задачи обязательно.<br />BR-07: Исполнителем может быть только участник данного пространства.<br />BR-08: Дедлайн не может быть в прошлом.|

**FR-06 — Отметка выполнения задачи**

|**Бизнес-правила**|BR-09: Если задаче назначен исполнитель - изменять статус может исполнитель и администратор пространства; если исполнитель не назначен - любой участник пространства.<br />BR-10: Повторяемость применяется только к задачам с включённой повторяемостью.|

### Критерии приёмки

***Критерии приемки к FR-01: Вход в приложение***

Основной сценарий:
- [ ] При вводе корректных учётных данных пользователь успешно авторизуется
- [ ] После входа открывается главный экран со списком пространств и возможностью создать/войти в пространство

Альтернативный сценарий:
- [ ] При выборе "Регистрация" пользователь может создать учётную запись и после успешной регистрации попадает на главный экран
- [ ] При выборе "Не помню пароль" система запускает сценарий восстановления доступа (отображает соответствующий экран/инструкции)

Валидация формата:
- [ ] Пустые поля логина/пароля не принимаются, отображается сообщение об ошибке

Проверка условий:
- [ ] При неверных учётных данных отображается сообщение "Неверный логин или пароль"
- [ ] После 5 неудачных попыток входа вход в данную учётную запись блокируется блокируется на 15 минут и отображается сообщение о блокировке

Сохранение данных:
- [ ] При успешном входе создаётся/обновляется пользовательская сессия
- [ ] При ошибке входа пользователь не авторизуется и сессия не создаётся

***Критерии приемки к FR-02: Создание пространства***

Основной сценарий:
- [ ] Пространство создаётся, если название указано
- [ ] Создатель пространства получает роль "администратор"
- [ ] Сгенерирован код приглашения
- [ ] Созданное пространство отображается в списке пространств пользователя и открывается после создания

Валидация формата:
- [ ] Если название не указано, система отображает сообщение об ошибке

Сохранение данных:
- [ ] При успехе сохраняются данные пространства и роль создателя "администратор"
- [ ] При ошибке пространство не создаётся

***Критерии приемки к FR-03: Получение кода приглашения***

Основной сценарий:
- [ ] Администратор может открыть экран приглашения и увидеть код приглашения
- [ ] Администратор может передать код приглашённому пользователю

Проверка условий:
- [ ] Пользователь без роли администратора не имеет доступа к получению/управлению кодом приглашения
- [ ] После генерации нового кода отображается новый код (отличается от предыдущего)

Сохранение данных:
- [ ] При генерации нового кода новый код сохраняется для пространства

***Критерии приемки к FR-04: Присоединение к пространству по коду***

Основной сценарий:
- [ ] При вводе корректного кода пользователь добавляется в пространство как "участник"
- [ ] Пространство появляется в списке пространств пользователя
- [ ] Пространство открывается после успешного присоединения

Проверка условий:
- [ ] При недействительном коде отображается сообщение "Неверный код приглашения"
- [ ] Если пользователь уже состоит в пространстве - система сообщает об этом и открывает пространство

Сохранение данных:
- [ ] При успехе сохраняется связь "пользователь-пространство" и роль "участник"
- [ ] При ошибке присоединения пользователь не добавляется в пространство

***FR-03 + FR-04:***
- [ ] При генерации нового кода предыдущий код становится недействительным (попытка присоединиться по старому коду приводит к ошибке "Неверный код приглашения")

***Критерии приемки к FR-05: Создание задачи по дому***

Основной сценарий:
- [ ] Задача создаётся и отображается в списке задач пространства
- [ ] При выборе исполнителя задача создаётся с назначенным исполнителем
- [ ] При включении опции "Добавить задачу в календарь" задача отображается в календаре пространства
- [ ] При назначении исполнителя отправляется push-уведомление о назначении
- [ ] При наличии дедлайна отправляется push-уведомление о дедлайне

Проверка условий:
- [ ] Если исполнитель не выбран, задача создаётся без исполнителя, push о назначении не отправляется
- [ ] Если дедлайн не задан, задача создаётся, push о дедлайне не отправляется

Валидация формата:
- [ ] Пустое название задачи отклоняется с сообщением об ошибке
- [ ] Дедлайн в прошлом отклоняется с сообщением об ошибке

Бизнес-правила:
- [ ] Исполнителем может быть только участник данного пространства

Сохранение данных:
- [ ] При успехе сохраняются данные задачи: название (обязательно), исполнитель/дедлайн/повторяемость/привязка к календарю - если указаны
- [ ] При ошибке задача не создаётся

***Критерии приемки к FR-06: Отметка выполнения задачи***

Основной сценарий:
- [ ] Статус задачи меняется на "выполнено"
- [ ] Если задача повторяющаяся - создаётся следующее повторение по расписанию

Бизнес-правила:
- [ ] Если назначен исполнитель - статус может изменить исполнитель и администратор пространства
- [ ] Если исполнитель не назначен - статус может изменить любой участник пространства

Сохранение данных:
- [ ] При успехе сохраняется новый статус задачи и время выполнения

***Критерии приемки к FR-07: Ведение списка покупок***

Основной сценарий:
- [ ] Позиция покупки добавляется в общий список и видна всем участникам пространства
- [ ] Позицию можно отметить как "куплено"
- [ ] Позицию можно отредактировать
- [ ] Позицию можно удалить

Валидация формата:
- [ ] Пустое название позиции отклоняется с сообщением об ошибке

Сохранение данных:
- [ ] При успехе изменения списка сохраняются (добавление/редактирование/удаление/статус "куплено")
- [ ] При ошибке изменения не сохраняются

***Критерии приемки к FR-08: Создание события календаря пространства***

Основной сценарий:
- [ ] Событие создаётся и отображается в календаре пространства

Проверка условий:
- [ ] Если выбраны участники - push о создании события отправляется выбранным участникам
- [ ] Если участники не выбраны - push о создании события отправляется всем участникам
- [ ] Если заданы сроки напоминаний - система отправляет push-напоминания в заданное время
- [ ] Если сроки напоминаний не заданы - push-напоминания не отправляются

Валидация формата:
- [ ] Пустое название события отклоняется с сообщением об ошибке

Сохранение данных:
- [ ] При успехе сохраняются данные события (название, дата/время, участники/без)
- [ ] При ошибке событие не создаётся
